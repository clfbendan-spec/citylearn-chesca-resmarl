\subsection{系统首页设计}
系统首页作为用户登录后的第一站，顶部摆放社区建筑总数、已接入数据集个数、已登记控制算法数量与历史完成实验总数的统计卡片；中部提供“浏览数据集”、“新建仿真任务”、“多任务指标对比”与“高峰时刻决策诊断”四个一键跳转卡片；底部用清晰的流程图提示用户标准实验步骤，降低初次使用者的操作门槛。

\subsection{算法与数据集配置页面设计}
配置页面采用“先选数据集和控制器类型，再自动展示对应参数”的智能联动设计，五类可选控制器的差异详见表\ref{tab:baselines}：
\begin{itemize}
    \item 当用户选择纯分层先验基线时，页面只显示负荷脉冲软门控下限$m_{\text{下限}}$与上限$m_{\text{上限}}$等规则参数，自动隐藏强化学习训练轮数等无关选项；
    \item 当选择CHESCA-ResMARL：先验引导残差混合控制时，页面自动展开残差夹断系数$\alpha$、三维动作通道屏蔽掩码与安全门控开关，并强制检查用户选择的预训练模型文件是否与目标数据集的建筑栋数一致；
    \item 当选择MARL：端到端区域协同多智能体控制时，页面展开训练总轮数、评估间隔轮数、区域峰值惩罚权重、经验回放池大小与多步回报步数等训练参数。
\end{itemize}
页面右侧内置代码查看与编辑窗口，研究人员可在该窗口直接检查或微调 Python 脚本；点击“提交运行”后，下方任务表格每隔 5 秒自动刷新一次当前训练轮数和最佳削峰指标。

\subsection{能源与KPI分析页面设计}
能源与KPI分析页面采用左右分栏设计：左侧支持同时勾选多个历史完成的仿真任务，利用ECharts绘制分组柱状图与五维雷达图\cite{echarts2024}，将不同策略在全时段峰值、日均峰值、电度电费、碳排放与负荷爬坡率五个维度上的优劣并排呈现；右侧结合分时电价背景色带（平谷期浅色、高电价期深色），绘制社区总负荷与光伏发电随时间变化的折线图，并支持将对比数据一键导出为CSV表格。

\subsection{决策轨迹页面设计}
决策轨迹页面专门用于解开强化学习的“黑盒”决策过程。页面将单栋建筑在每个小时步的动作拆解为三条并排曲线：分层基线动作$a_{\text{基线}}$、强化学习残差修正量$\delta$以及经过三层安全包络裁剪后的最终动作$a_{\text{最终}}$，并在下方同步对齐展示该建筑同一小时的室内温度、目标温度、电池剩余电量（SOC）与当步电价。鼠标悬停在晚间用电尖峰时刻时，几张图表同步显示该小时的具体数值，记录控制器提前储电、尖峰时刻协同放电压低社区峰值的过程。

\subsection{实验数据集来源与标准化预处理}
实验数据的真实性是评估算法可比性的前提。本平台接入的实验数据源自美国加利福尼亚州真实零净能耗住宅社区的实测运行记录与典型气象年数据（由国际开源基准CityLearn整理发布\cite{citylearn2020,citylearn2024}）。每栋住宅均配备了冷暖空调热泵、生活热水储水箱、屋顶太阳能光伏板以及户用磷酸铁锂蓄电池（单楼电池容量为$3.2\text{ kWh}$、最大充放电功率为$2.7\text{ kW}$）。在将原始测量数据导入平台前，统一执行三步标准化预处理：
\begin{enumerate}
    \item 时间粒度统一按小时对齐：将原本按分钟记录的电表功率数据汇总转换为以1个小时为1步的逐时用电量数据（单位：$\text{kWh}$），例如连续测试30天即对应约$30 \times 24 = 720$个小时步的月度测试期。
    \item 缺失值插补与物理边界检查：对传感器偶发的单点缺失采用前后相邻小时线性插值补齐，并严格检查所有电池剩余电量（SOC）是否在$[0, 1]$之间、不可调家电负荷与光伏发电功率是否均大于等于$0$。
    \item 按测试目的划分为四套直观的中文命名数据集（具体用途见表\ref{tab:datasets}）。
\end{enumerate}

\section{运行日志的自动化解析与归档实现}
Python 仿真进程在后台运行时，会产生两类输出信息：一类是打印在控制台里的实时文字日志，另一类是保存在任务文件夹里的结构化结果文件。后端设计了双通道解析归档器来自动处理这两类信息，流程如图\figref{日志归档流程图}所示。
\begin{figure}[!htbp]
    \centering
    \includegraphics[width=0.88\textwidth]{./images/pictures/日志归档流程图.png}
    \centering\bicaption{仿真运行日志与评估指标自动化解析归档流程图}{Flowchart of automated parsing and archiving for simulation logs and evaluation KPIs}
    \label{日志归档流程图}
\end{figure}

具体实现包含三个步骤：
\begin{enumerate}
    \item 训练期间的原子进度更新：在100轮强化学习训练过程中，Python端每完成一次评估，就把当前轮数、总轮数和历史最佳峰值比写入临时进度文件，再通过操作系统原子替换指令瞬间发布为最新版本，确保Java后端每隔5秒读取时不会读到写了一半的残缺文件。
    \item 任务结束后的指标自动归档：当仿真进程正常结束时，Java后端的日志解析器自动读取任务文件夹下的评估指标汇总文件（含全时段峰值比、日均峰值比、电度成本比、碳排放比、爬坡率比、热舒适越界率等关键指标）与社区评估摘要文件（包含关键小时步的电池充放电与室温等摘要），将上述指标自动批量归档到任务专属输出目录。
    \item 异常报错的自动捕获与留痕：如果Python进程因参数配置错误等原因中途失败，后端立即将数据库中的任务状态更新为“失败”，并将最后50行错误堆栈保存到错误日志文件中，前端页面可点击该记录查看完整报错原因。
\end{enumerate}

\section{多智能体算法集成与异步任务调度实现}
单次 100 轮 MARL 训练需十余分钟，远超浏览器连接容忍时长。系统因此引入基于后台线程池与独立进程隔离的异步任务调度机制，前后端与 Python 算法进程的交互时序如图\figref{异步调度时序图}所示。
\begin{figure}[!htbp]
    \centering
    \includegraphics[width=0.90\textwidth]{./images/pictures/异步调度时序图.png}
    \centering\bicaption{前后端与Python多智能体训练进程的异步任务调度时序图}{Sequence diagram of asynchronous task scheduling between frontend, backend, and Python MARL process}
    \label{异步调度时序图}
\end{figure}

整个异步调度过程分为四步：
\begin{enumerate}
    \item 任务创建与快照隔离：用户在网页点击“提交任务”后，Spring Boot后端先检查数据集与模型建筑数是否匹配；检查通过后立即生成任务编号、在数据库中插入一条状态为“运行中”的记录，并在磁盘上创建该任务专属的文件夹，将用户当前填写的参数和脚本复制一份存为快照，随即向前端返回“提交成功”。
    \item 后台拉起确定性Python子进程：后端异步线程池接手该任务，通过 Java 进程构建器启动独立的Python子进程，并在启动环境变量中强制注入进程哈希种子（取值为0），消除多智能体字典遍历顺序带来的随机分岔。
    \item 前端周期轮询实时进度：在Python子进程训练期间，前端页面每隔5秒调用一次进度查询接口，后端直接读取任务文件夹下的训练进度文件并返回当前训练到了第几轮、当前最佳全时段峰值是多少，实现流畅的进度条展示。
    \item 最优检查点恢复与结果归档：训练到达设定轮数后，Python程序自动重新加载整个训练过程中表现最好的检查点权重（Best Checkpoint），跑完一遍完整评估并生成评估指标汇总文件与逐时动作轨迹文件；Java后端监听到进程结束后，自动将所有评估指标与逐时轨迹归档到任务专属输出目录，并将任务状态更新为“已完成”。
\end{enumerate}

\section{本章小结}
本章按“前端—数据—后台—存储—调度—界面验收”的顺序完整阐述了可视化管理平台的工程实现。前端侧覆盖四个核心交互页面；数据侧完成加州社区实测数据的标准化预处理与四套数据集的命名规范化，控制器侧通过统一的注册表接入五类对比与自研策略；后台侧实现训练进度的原子化更新、评估指标的自动入库与异常报错的自动留痕；存储侧搭建 MySQL 关系表与 CSV 文件相结合的双层结构；调度侧构建确定性哈希种子注入与最佳检查点自动恢复机制；最后给出五张界面截图作为系统可运行的工程佐证。前述各项落地模块共同支撑了第 5 章两类 MARL 算法的可比、可复现实验。
