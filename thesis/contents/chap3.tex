\chapter{系统需求与架构分析}
\section{需求分析}
前文已阐述建筑群节能控制面临的四类核心难题，并构建了面向不同工程先验条件的双模式多智能体协同控制体系——面向有专家规则场景的“先验引导残差混合控制（方案一）”与面向无先验规则场景的“端到端区域协同多智能体强化学习（方案二）”。为支撑算法模型、确定性复现协议与两部制电价核算方法走出命令行脚本、真正被园区工程与科研人员便捷地调用和诊断，本章按软件工程的四个步骤依次推进可视化管理平台的系统分析与架构设计：需求分析、总体架构与技术选型、核心功能模块设计、数据库概念建模\cite{vue2024,xupengtao2020,springboot2024,wangyonghe2016}。

平台主要服务于三类核心用户角色：
\begin{enumerate}
    \item 园区能源管理人员——关注社区每月的综合电费账单、全月最大需量峰值降幅、碳排放总量以及住户室内温度是否舒适。他们需要直观的多维指标汇总卡片、工商业两部制电价账单对比视图，以及在晚间用电尖峰时刻能够清晰看懂“为什么系统此时指令各楼电池集中放电、同步关小空调”的白盒化决策图表。
    \item 算法研发与实验人员——需要在Web界面上灵活切换不同规模与季节的社区数据集、配置双模式算法超参数（如脉冲软门控阈值、残差修正幅度上限$\alpha$、动作通道屏蔽掩码、区域峰值惩罚权重、经验回放池容量、多步回报步数与随机种子）、一键提交后台异步训练或评估任务并实时监控收敛进度，以及按小时步对齐比对基线动作、残差修正量与安全裁剪后的最终执行动作。
    \item 系统运维管理员——负责管理系统账号与角色菜单访问权限、登记新导入的标准社区数据集并校验其建筑栋数与控制器模型的兼容性、维护算法脚本库版本以及排查异常中断任务的错误日志。
\end{enumerate}

三类用户的业务闭环由四大核心模块承载：系统管理、数据与基准管理、算法与异步实验管理、可视化与决策诊断分析。整体功能结构如图\figref{功能模块图}所示。

（1）系统管理模块需求。涵盖用户认证登录、基于角色的菜单权限控制（RBAC）以及异步任务状态消息提醒。系统管理员可新增、编辑或停用账号，并为不同角色分配可见菜单与操作权限（如普通访客仅可浏览历史看板，研发人员可修改超参数、编辑脚本并提交训练任务）；用户密码采用单向哈希加密存储，接口层对上传文件后缀与查询参数进行严格白名单校验；当后台耗时数十分钟的强化学习训练任务完成或异常退出时，系统自动向导航栏推送未读通知消息。

（2）数据与基准管理模块需求。围绕标准社区产消数据集\cite{citylearn2020,citylearn2024,gymnasium2024}，统一纳管各栋住宅的不可调家电负荷、光伏发电、室内外温湿度、太阳辐射、分时电价与电网碳排放因子等逐时序列。系统需清晰登记每套数据集的中文名称、建筑栋数（3栋或6栋）、仿真总小时数及适用控制器范围，支持原始时序数据的分页检索与CSV格式导出；尤为关键的是，在用户提交仿真任务前，系统必须执行前置兼容性校验——自动核对所选预训练模型权重的智能体数量与目标数据集的建筑栋数是否一致，若不匹配则立即弹窗拦截并给出明确提示，杜绝后台进程因维度冲突崩溃。

（3）算法与异步实验管理模块需求。系统需将五类对比与自研控制器（无控制参考基准、传统冷热电规则控制、改进型分层先验控制基线、先验引导残差多智能体混合控制、端到端区域协同多智能体强化学习）统一纳入算法注册表管理。参数配置页需支持根据当前选中的控制器类型动态展开或折叠专属参数面板，并提供带语法高亮的在线Python脚本查看与微调功能；每次提交任务时，后端自动生成全局唯一任务编号（UUID），将当前参数与脚本保存为任务专属快照，交由后台异步工作线程池拉起独立Python子进程执行，并通过轮询协议实时回传当前训练轮数、已用时间与最佳削峰指标。

（4）可视化与决策诊断分析模块需求。系统需提供由宏观到微观的三层可视化诊断能力：一是多任务KPI对比层，支持同屏勾选多组实验任务，通过分组柱状图与五维雷达图直观对比全时段峰值比、日均峰值比、电度成本比、碳排放比、爬坡率比及热舒适越界率；二是社区负荷与电价时序层，通过多轴联动折线图展示社区总净负荷、分时电价、电网碳强度与各楼电池平均电量随时间的演变；三是逐小时白盒决策轨迹层，支持定位到任意关键高峰时刻（如第28天晚上22时全月最高峰），同屏对齐展示各栋建筑的规则基线动作$a_{\text{基线}}$、强化学习残差修正量$\delta$、通道掩码状态与最终执行动作$a_{\text{最终}}$，将黑盒神经网络转化为透明可解释的工程决策过程。

\subsection{系统非功能性需求分析}
平台需在多轮次强化学习训练与高频交互分析下保持工程可靠性，对应非功能性指标分为三组：
\begin{enumerate}
    \item 安全性与异常容错性。持久层数据库查询全部采用预编译参数化绑定以根除SQL注入风险，文件流读取接口严格校验任务归档根目录边界以防止路径穿越；当Python算法子进程因参数越界或显存不足异常退出时，Java后端须自动捕获标准错误流日志、将任务状态安全置为“异常失败”并完整留痕，严禁引起主Web服务阻塞或崩溃\cite{mysql2024}。
    \item 交互响应速度与多任务并发隔离。遵循“轻量查询同步极速返回、重型仿真后台异步解耦”的设计准则，常规列表检索与KPI图表加载接口响应耗时须控制在$100\text{ ms}$以内；当多名研发人员并发提交不同随机种子的训练任务时，各任务拥有独立归档目录并在启动入口强制锁定进程哈希种子（取值为 0），训练进度文件采用“临时文件写入+原子重命名替换”机制，确保并发读写零冲突、实验复现零偏差。
    \item 跨终端兼容性与架构可扩展性。前端采用响应式栅格布局\cite{elementui2024}与自适应画布重绘机制\cite{echarts2024}，兼容Chrome、Edge、Firefox等主流浏览器；数据库算法参数表采用灵活的“参数键—参数值—所属分组”窄表结构，后续新增控制策略或奖励权重时无需修改数据库表结构（零DDL变更）。
\end{enumerate}

\section{系统总体架构与技术栈选型设计}
\subsection{浏览器/服务器（B/S）四层总体架构}
系统采用前后端分离、Java业务调度与Python算法执行进程解耦的浏览器/服务器（B/S）四层架构——用户无需在本地安装复杂的深度学习环境，直接通过标准网页浏览器即可完成数据集浏览、多智能体训练配置与逐时轨迹诊断。系统自上而下依次划分为客户端浏览器交互层、前端Web展示服务层、后端业务调度应用层、数据持久化与算法执行层，总体架构如图\figref{系统架构图}所示。
\begin{figure}[!htbp]
    \centering
    \includegraphics[width=0.85\textwidth]{./images/pictures/系统架构图.png}
    \centering\bicaption{系统浏览器/服务器（B/S）四层总体架构图}{Four-tier B/S system architecture diagram}
    \label{系统架构图}
\end{figure}

\begin{enumerate}
    \item 客户端浏览器交互层：运行于用户终端浏览器，负责渲染单页应用视图、执行表单参数范围与必填项前端校验、维护登录会话令牌（Token），并通过异步HTTP请求与后端交互。
    \item 前端Web展示服务层：基于Vue框架与Element UI组件库构建模块化单页应用\cite{vue2024,xupengtao2020,elementui2024}，集成Apache ECharts可视化引擎实现多维KPI雷达图、分时电价背景色带与多通道动作分解图的动态渲染\cite{echarts2024,wangzhiwen2020}。针对长耗时强化学习训练，前端采用5秒周期的非阻塞轮询机制实时更新训练轮次与最佳峰值曲线。
    \item 后端业务调度应用层：基于Java语言的Spring Boot框架提供标准RESTful接口服务\cite{springboot2024,wangyonghe2016}，内部按“控制器层（Controller）—业务逻辑层（Service）—数据访问层（Mapper/DAO）”三级职责解耦，统一负责权限认证拦截、模型与数据集兼容性校验、全局唯一任务ID分配、后台异步线程池调度以及仿真产物（CSV与JSON文件）的自动化解析入库。
    \item 数据持久化与算法执行层：采用“MySQL 8.0关系型数据库 + 任务专属文件归档目录 + Python独立算法进程池”协同工作的混合架构\cite{mysql2024,ouyangguixiu2022}。MySQL负责存储高频检索的账号权限、数据集目录、任务状态与汇总KPI指标；文件系统按任务ID隔离存放逐小时时序明细（CSV）与神经网络检查点权重；Python算法端通过Gymnasium接口封装CityLearn仿真环境\cite{citylearn2020,towers2024gymnasium,gymnasium2024}，依托PyTorch深度学习框架\cite{paszke2019}与Ray RLlib分布式多智能体框架\cite{liang2018rllib}独立执行方案一与方案二的训练推演。
\end{enumerate}

\section{核心功能模块设计}
\subsection{系统管理模块}
系统管理模块包含账号生命周期管理、角色权限映射与异步消息中心三个子单元。管理员可在后台创建研发或访客账号并绑定角色权限，前端路由守卫根据登录返回的权限列表动态裁剪侧边栏菜单（例如对普通访客自动隐藏“在线脚本编辑”与“系统用户管理”入口）；每当后台异步训练或评估任务状态由“运行中”跃迁为“已完成”或“失败”时，消息中心自动生成状态变更通知，方便研究人员及时查看实验结果。

\subsection{数据与基准管理模块}
数据与基准管理模块负责四套标准社区数据集（标准月度评估集、长周期三月评估集、六建筑扩容测试集与全年跨季节测试集）的统一登记、在线浏览与兼容性校验。模块记录每套数据集的建筑数量、时间步长与文件路径，支持按建筑编号分页查看逐小时家电固定负荷、光伏发电功率、室内外温湿度与分时电价，并提供一键导出CSV功能，方便研究人员在实验前开展探索性数据分析。

\subsection{算法与异步实验管理模块}
算法与异步实验管理模块贯通“控制器选择—分组参数配置—兼容性拦截—异步进程调度—最优权重归档”的完整生命周期。配置页面将数十项算法参数按逻辑划分为四个折叠面板（基础仿真设置、分层先验基线参数、先验残差混合控制参数、端到端区域协同强化学习参数），切换控制器时自动显隐对应面板；任务提交后，后端通过 Java 进程构建器启动注入了进程哈希种子（取值为0）的独立 Python 子进程，实时解析控制台输出与训练进度文件，并在训练结束时自动恢复历史最佳检查点权重导出最终评估指标。

\subsection{可视化与决策诊断分析模块}
可视化与决策诊断分析模块由“多任务KPI综合对比”、“社区能源与环境时序分析”和“逐小时白盒决策轨迹回放”三个联动视图组成。用户可在KPI对比页直观检验方案一与方案二相对于单楼独立强化学习及传统规则的削峰节费优势；随后跳转至决策轨迹页，将时间轴定格在晚间用电尖峰时刻，同步查看三栋建筑的室内温度、电池剩余电量（SOC）、分时电价以及“基线动作—残差修正—安全门控裁剪”的全链路分解数值。

\section{数据库概念设计}
本系统关系型数据库选用MySQL 8.0（统一采用\texttt{utf8mb4}字符集）。遵循“高频查询索引与汇总指标进关系库、海量逐时浮点序列存文件系统”的混合存储设计原则，数据库概念模型围绕三大核心业务实体簇展开：第一类是建筑与外部环境时序实体簇（涵盖各栋建筑每小时温湿度、冷热电负荷、光伏发电以及室外气象、分时电价、电网碳强度）；第二类是算法脚本、数据集与仿真任务调度实体簇（涵盖系统用户、数据集目录、注册算法脚本、仿真任务主表及任务运行参数表）；第三类是任务输出文件索引实体簇（涵盖任务级与建筑级评估结果 CSV 文件、检查点权重文件及逐时动作轨迹的路径表）。
